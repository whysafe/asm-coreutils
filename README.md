# asm-coreutils: cat, wc, hexdump и rev на ассемблере x86-64

Четыре знакомые утилиты Linux, написанные на чистом ассемблере NASM. Без libc и без единой сторонней функции: только системные вызовы `read`, `write`, `open`, `close`, `fstat`, `brk` и `exit`. Вывод совпадает с GNU coreutils и util-linux байт в байт, это проверяется в CI на каждый push.

```text
$ ./bin/wc tests/data/poem.txt
 10  44 246 tests/data/poem.txt

$ printf 'one two\nthree' | ./bin/wc
      1       3      13

$ ./bin/hexdump -C tests/data/hello.txt
00000000  48 65 6c 6c 6f 2c 20 77  6f 72 6c 64 21 0a        |Hello, world!.|
0000000e

$ echo 'stressed desserts' | ./bin/rev
stressed desserts

$ ls -l bin/            # статические ELF без libc; после strip около 9 КБ
-rwxr-xr-x 13232 cat
-rwxr-xr-x 13952 hexdump
-rwxr-xr-x 13320 rev
-rwxr-xr-x 14704 wc
```

`rev` переворачивает байты, а не символы, поэтому кириллица в UTF-8 после него становится нечитаемой. Так же ведёт себя `rev` из util-linux в локали C, и пример выше показан именно для латиницы.

## Возможности

**cat** `[-n] [файл...]`
- Склеивает файлы и stdin (`-` или без аргументов), бинарные данные проходят без изменений.
- `-n` нумерует строки в формате GNU (`%6d\t`), сквозная нумерация через все файлы.

**wc** `[-lwc] [файл...]`
- Строки, слова и байты, флаги в любом сочетании (`-lw`, `-c -l`), `--` как конец опций.
- Слова разделяются пробелом, табуляцией, `\n`, `\v`, `\f` и `\r`, как в GNU wc в локали C.
- Строка `total` для нескольких файлов.
- Ширина колонок по правилам GNU: по числу цифр суммарного размера обычных файлов, не меньше 7, если среди входов есть пайп.

**hexdump** `-C [файл...]`
- Канонический вывод: смещение, 16 байт в hex двумя группами по 8 и колонка ASCII.
- Повторяющиеся строки сворачиваются в `*`, как в оригинале.
- Несколько файлов дампятся одним потоком со сквозным смещением.

**rev** `[файл...]`
- Переворачивает каждую строку. Строка может быть любой длины: буфер в куче растёт через `brk`.
- Последняя строка без `\n` обрабатывается так же, как в util-linux.

**Общее**
- Ошибки в стиле GNU: `wc: nosuch.txt: No such file or directory`, ненулевой код выхода, обработка остальных файлов продолжается.
- `EINTR` при чтении и записи повторяется, частичная запись дописывается.
- Код возврата 1 при ошибке записи, например в закрытый пайп.

## Запуск

Нужны Linux x86-64, `nasm` и `ld` (binutils).

```bash
sudo apt install nasm        # Debian/Ubuntu
make                         # бинарники появятся в bin/
make test                    # сравнение с системными утилитами
./bin/cat -n Makefile
```

## Как устроено

```
lib/io.inc     номера системных вызовов, константы, соглашение о вызовах
lib/io.asm     обёртки над syscall, буферизованный stdout, вывод чисел, сообщения об ошибках
src/cat.asm    cat
src/wc.asm     wc
src/hexdump.asm
src/rev.asm
tests/run.sh   интеграционные тесты против GNU coreutils / util-linux
```

- **Соглашение о вызовах** внутри программ: подмножество System V AMD64. Аргументы в `rdi`, `rsi`, `rdx`, результат в `rax`, `rbx`, `rbp` и `r12`–`r15` сохраняются. Ошибки возвращаются как `-errno`, как это делает ядро.
- **Ввод** читается блоками по 64 КБ прямо в статический буфер. **Вывод** копится в своём буфере на 64 КБ и сбрасывается одним `write`, поэтому `cat` большого файла делает несколько системных вызовов, а не по одному на строку.
- **wc** перед подсчётом делает `fstat` для каждого файла: так он заранее знает ширину колонок, как GNU wc.
- **hexdump** держит текущую 16-байтную строку и предыдущую, чтобы сворачивать повторы в `*`.
- **rev** собирает строку в куче, которую сам растит через `brk`, потому что строка может быть больше любого фиксированного буфера.
- Каждая программа подключает `io.o` и объявляет `prog_name` для сообщений об ошибках. Компоновка статическая через `ld`, без стартового кода C: точка входа `_start` сама разбирает `argc`/`argv` со стека.

## Тесты

`make test` запускает 54 проверки. Каждая команда выполняется дважды: с нашими бинарниками первыми в `PATH` и с системными утилитами. Stdout и код выхода (а для части случаев и stderr) должны совпасть байт в байт.

- Пустые файлы, файлы без завершающего `\n`, stdin через `<`, пайп и `-`.
- Все 256 значений байта, 150 КБ случайных данных, 40 000 строк, строка длиной 340 КБ.
- Размеры на границах буфера, повторы для `*` в hexdump, разные пробельные символы для wc.
- Отсутствующие файлы посреди списка.
- Проверка, что бинарники статические и не тянут libc.

В GitHub Actions всё собирается и тестируется на Ubuntu 24.04.
